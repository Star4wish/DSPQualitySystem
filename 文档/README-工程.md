# DSP 品质系统 Mod（DSP Quality System）

一句话：把原版「增产剂 inc」重构成 **0–10 级品质点数**——产物继承原料品质、建筑品质提升产物品质、高品矿机采出高品矿。适用于 **Dyson Sphere Program 0.10.35**（BepInEx 5）。

- 当前版本：**v0.11.10**（2026-10-26 构建；DLL SHA256 `08EE21F7D3EBD51CA169929C53FD06398745BB7BF805B8CD5222417DEEE023B1`）
- 已实现里程碑：**M0**（品质点数线性表）、**M1**（产物继承 + 输出写品质）、**M2**（建筑品质捕获/绑定/升品/拆除清理）、**M3**（矿机品质 + JSON 存读档；矿机项实机验证待补）、**M4/P2**（分馏塔品质）、**P3 阶段1**（建筑品质 → 制造/采集速度）、**P3 阶段2a**（建筑品质 → 物流塔充电上限；v0.11.0 改为"上限+电网需求"）、**P3 阶段2d**（拆除返还品质点数）、**P3 阶段2e**（矿机多重概率升级 + 高点数建筑额外升品）、**P4**（背包建筑品质隔离；v0.10.0，v0.11.1 起覆盖背包"整理"按钮）、**P3 曲线**（v0.11.2：点数加成改为分段曲线，10 点 = 2.00×）、**P5 阶段A**（v0.11.2：蓝图携带建筑品质点数）、**P4 容器隔离**（v0.11.3：储物仓等 `EStorageType.Default` 容器也按点数分格；物流塔内部/机甲燃料弹药格不隔离）；**P5 阶段A 结算**（v0.11.4 引入；v0.11.5 按用户口径改为**通用优先消耗**——手持建造与蓝图粘贴时优先消耗玩家持有的最高品质同类建筑物品，落成点数 = 实际消耗物品的点数；蓝图携带品质改为**可选、默认关闭**）、**P6 视觉标记**（v0.11.10：10 点建筑头顶金色光环——256×256 程序生成**空心**环形贴图（内孔全透明、环体实心、外圈柔和光晕）、面向相机的 billboard，浮在建筑最高点上方 `tenPointHaloLift`，缓慢自转 + 轻微浮动 + alpha 呼吸；加法混合、ZTest Always/renderQueue 3100，纯视觉、不改模型材质/存档。v0.11.6–v0.11.8 的屏幕描边保留为实验性选项、默认关闭））
- 插件 GUID：`dsp.qualitysystem`；配置文件 `BepInEx\config\dsp.qualitysystem.cfg`
- 开发交接：见交接包根目录 `HANDOFF.md` 与 `DSP品质系统-MOD开发文档.md`

## 安装

1. 确认游戏已装 **BepInEx 5.4.x**（含 `BepInEx\core` 与 `winhttp.dll`）。
2. 把 `DSPQualitySystem.dll` 放进 `Dyson Sphere Program\BepInEx\plugins\DSPQualitySystem\`。
3. 运行时依赖：**BepInEx 5** + **CommonAPI**（`BepInEx\plugins` 里已有即可）。不需要 LDBTool、不需要 DSPModSave。
4. 启动游戏，主菜单即生效；日志在 `BepInEx\LogOutput.log`，搜索 `DSP Quality System` / `[QSystem]`。

卸载：删掉插件 DLL 即可（存档里的 `.dsv` 不受影响，旁挂品质 JSON 保留但不再被读取）。

## 玩法说明

- **品质 = 每件物品携带的 inc 点数（0–10）**。喷涂机 Mk.I / Mk.II / Mk.III 分别给 1 / 2 / 4 点。
- **线性表**：1 点品质 = 原版 inc 100 的效果，即 **+10% 产出、+25% 电耗**；2 点 = +20% / +50%，4 点 = +40% / +100%，以此类推到 10 点。
- **产物继承**：制造台/熔炉开新一批时，取**所有输入槽的每件平均点数的最小值**作为本批品质，产物继承该品质（多原料取最低，缺料/不同品质混投都按平均后取 min）。
- **建筑品质**：手持带品质的材料建造时，材料品质写入建筑（每件平均点数，0–10）。建筑品质决定两件事：
  - **升品概率**：每生产一个周期，有 `建筑点数 × buildingChancePerPoint` 的概率让本批产物品质 +1（上限 `maxQuality`，受 `maxUpgradeChance` 限制）。v0.9.0：点数**高于** `extraUpgradeAbove`（默认 6，即 7/8/9 点）时再多判定一次（两次都成则 +2）；点数**达到** `doubleUpgradeAt`（默认 10 点）时必定 +2。分馏塔不享受这两条额外规则（保持 v0.8.0 的单次升品）。
  - **矿机**：每件矿的升品判定次数 = `floor(建筑点数 / 2)`（2 点→1 次、4 点→2 次、6 点→3 次、10 点→5 次；0/1 点→0 次），每次成功率仍为 `建筑点数 × minerChancePerPoint`（%/次，受 100% 限制），每次成功 +1 点，**单件上限 = 判定次数**。默认 2%/点下 4 点矿机期望 0.16 点/件、10 点矿机期望 1.0 点/件。
  - **分馏塔**：每成功分馏一件，按输入平均点数（`fluidInputInc / fluidInputCount`，即原版 num3）继承品质，再走一次升品判定；出货时把该点数写在物品上（传送带堵住不消耗，下个周期重试）。切换配方会清空该塔未出货的品质池。
  - **速度（P3 阶段1）**：每点建筑品质给本栋制造台/矿机加固定比例的速（v0.11.2 起默认 `speedBonusMode=curve`：按点数查固定曲线表，10 点 = **2.00×**；`linear` 模式才用 `speedPerPoint`/`maxSpeedBonus`）。只作用本栋建筑、**不额外耗电**、不改存档字段；`speedBonus=false` 可一键关闭。并行设施 tick 的星球兜底计数见 DEVLOG §17.5。
  - **物流塔充电上限（P3 阶段2a，v0.11.0 改版）**：每点建筑品质把本塔**每 tick 可充入的电量上限**（原版 `energyPerTick`）按同一曲线表提高（v0.11.2 默认 `curve`：10 点 = 2.00×；`linear` 模式才用 `chargePerPoint`/`maxChargeBonus`），并同步把需求 `requiredEnergy` 抬到同样数值——电网供电充足时真实提速，供电不足时按电网比例分配。**总电量上限 `energyMax` 不变、单位时间取电上升**（不是省电）；值每 tick 由原版重算，不写入存档；`chargeBonus=false` 可一键关闭。v0.11.0 起旧"放大瞬时 power"的实现已退役（两者对乘积等价，但后者不申报需求）。
  - **优先消耗最高品质建筑物品（v0.11.5，手持建造 + 蓝图粘贴通用）**：建造/粘贴一栋建筑时，若玩家持有同种建筑物品的多个不同点数叠，**先消耗点数最高的那件**（手上同种物品优先于背包；背包内每件点数最高者优先、同点数取低索引格；严格更高才换手，同点数不换）。建筑落成点数 = 实际被消耗那件物品的点数，所以拿 10 点物品贴 0 点蓝图也会落成 10 点。只影响"消耗建筑物品"这一步，其它取放/分拣/物流保持原版；`preferHighQualityConsume=false` 关闭。
  - **拆除返还（P3 阶段2d）**：拆除建筑时，把它的品质点数写到返回背包的物品上（`giveDismantleInc`，默认 `true`），这样重建后点位不丢。只覆盖游戏内 GUI 拆除路径；一次拆多栋叠放建筑时点数作用于整栈物品；蓝图复制/粘贴仍为 0 品。
  - **背包隔离（P4，v0.10.0；v0.11.1 补上"整理"按钮）**：玩家背包里同种建筑按每件点数分格，例如 4 点熔炉与 0 点熔炉各占一格；同点数仍合并；矿石/材料等非建筑照原版合并。点背包的"整理/排序"按钮也不会再把不同点数的同类建筑并成一格（原版 `StorageComponent.Sort` 会被前缀接管重排）。配合拆除返还，拆下来的 4 点建筑回背包后不会与 0 点混叠，重建仍是 4 点。v0.11.3 起（`isolateStorageContainers=true`）该规则同样作用于储物仓等通用容器，容器"整理"按钮也按点数重组；物流塔内部与机甲燃料/弹药格仍保持原版平均语义。
  - **升品判定日志（v0.11.1，只读）**：`debugProbes=true` 时每次产物升品判定会打一条 `[QSystem][roll] eid=… in=… bld=… mode=… base=… extra=… pooled=…`（每个建筑前 20 条），用于核对高分建筑（7/8/9/10 点）的"额外升品"规则；它只观察、不改变随机数顺序与结果。
  - **蓝图携带品质（P5 阶段A，v0.11.2；v0.11.5 起默认关闭）**：开启 `blueprintQuality=true` 时，复制蓝图会把已有建筑的品质点数写进参数尾部（`magic + inc`），粘贴后建筑按记录恢复；默认关闭，关闭时蓝图与原版逐字节一致，粘贴落成按"实际消耗物品点数"（由上面"优先消耗"决定）。卸载本 Mod 后，带标记的蓝图仍可被原版正常复制/粘贴/存档（原版只按长度读参数，多余 2 个 int 被忽略）。
- **拆除**：拆掉建筑会清空该建筑的品质数据（原地重建不会继承旧点数），但物品本身会带回它的点数（P3 阶段2d）。
- **存档**：品质数据旁挂在 `BepInEx\config\DSPQualitySystem\saves\<存档槽名>.json`，随游戏存档槽名一一对应；读档时校验存档名与银河种子，不一致自动忽略（不会串档）。

## 已知限制（照实说明，不是 bug）

- **拆除返还有已知边界**：只覆盖 GUI 拆除路径（批量/脚本/其它 mod 触发的拆除维持原版 inc=0）；多栋叠放建筑一次拆除时点数作用于整栈物品，未逐件拆分。
- **矿机多段升级的期望随点数平方增长**（v0.9.0 设计取舍）：判定次数 = 点数/2、每次成功率 = 点数 × `minerChancePerPoint`，所以期望点数 ≈ 点数² × `minerChancePerPoint` / 200（默认 2%/点时：4 点→0.16、10 点→1.0 点/件）。嫌强可调低 `minerChancePerPoint`（沿用原配置键，未新增）。
- **隔离只覆盖建筑类物品与特定容器**：非建筑物品仍按原版合并；交付包（DeliveryPackage）、手持物品、`AddItem` 指定格路径仍按原版合并；"整理"按钮已被 v0.11.1 的 `StorageComponent.Sort` 前缀覆盖，但界面手动拖拽/拆分（直接写 GRID）仍绕过本补丁，可能把不同点数合并回一格（已知边界，见 DEVLOG §21.7 / §23）。
- **容器隔离的边界（v0.11.3）**：只覆盖玩家可交互的通用 `Default` 储物容器（储物仓、战场分析基站等）；**物流塔内部**（`StationStore` 一种物品一格、整格总点数）、**机甲燃料/弹药/炸弹/战斗机格**、**过滤容器**、**储液罐（`TankComponent`，每罐段一格）** 均不隔离，保持原版平均语义（结构上无法逐件保留点数）；`isolateStorageContainers=false` 时与 v0.11.2 完全一致。
- **优先消耗与蓝图品质的边界（v0.11.5）**：优先消耗只作用于"手持建造 / 蓝图粘贴"的建筑物品消耗步骤，普通取物、分拣器、物流塔、容器进出仍是原版顺序；换手时原手持整叠会放回背包（可能多占一格）；材料不足产生的未付款预建（半透明）补付发生在后续帧、点数无法追溯，补付后按 0 点落成；`blueprintQuality` 默认关闭，开启后蓝图才会携带/恢复点数（此时蓝色记录优先于消耗物品）；带图标传送带的标记预览、第三方蓝图工具、把蓝图分享给未装本 Mod 的玩家时不识别标记（当普通蓝图用）。若想恢复 v0.11.2 的“蓝图保品质”行为，把 `blueprintQuality` 设为 `true`（此时蓝图记录优先于消耗物品）。
- **分馏塔品质是"双重收益"（首版保留，非 bug）**：输入品质既按原版 `Cargo.accTableMilli` 提高分馏成功率，又通过本 Mod 继承/升品到产物，等于点数同时作用于成功率与产物品质（详见 DEVLOG §12.3、§16）。
- **建筑自身性能强化做了 P3 阶段1 + 阶段2a**：制造台/矿机按建筑品质加速（**不额外耗电**）、物流塔按建筑品质提高充电速度上限（**总电量不变、单位时间取电上升**，是平衡选择非 bug）；船速/运力、能量枢纽、电力塔范围等后续阶段未做（详见开发文档 §8.D 与 `_reports\task3-design.md`）。
- **物流塔充电加成的两条已知边界（v0.11.0）**：①`isCollector`/`isVeinCollector`（轨道采集器/矿脉采集器）不调用 `SetPCState`，因此不受充电加成；②`energyPerTick` 虽是存档字段但每 tick 由原版重算，若恰好在加成的同一帧存档，读档后首 tick 最多多充一 tick 的电量（自我修正，无 schema 变化，详见 DEVLOG §22.8）。
- **并行设施 tick 的 planetId 兜底**：后台/并行线程上的建筑用"最近一次串行 tick 的星球"兜底，单机单星球无差异；日志 `[QSystem][speed] … fallback=` 可观测（详见 DEVLOG §17.5）。物流塔充能只用实例字段，不依赖该兜底。
- **存档旁挂 JSON**：删掉 `config\DSPQualitySystem\saves\*.json` 等于品质清零，但**不影响** `.dsv` 存档本体；跨机器拷贝存档时记得一起带走 json。
- 品质数值只用于本 Mod 的产物/建筑逻辑，**不改变物品堆叠上限与传送带规则**。

- **视觉标记（P6，v0.11.10）**：当前星球上点数达到 `maxQuality`（默认 10）的建筑头顶会显示一圈**金色光环**（256×256 程序生成空心贴图、面向相机、缓慢自转 + 轻微浮动 + 呼吸），浮在建筑最高点上方 `tenPointHaloLift`（默认 1.2m）；远处按距离缩小、超过 120m 不画、同屏最多 `tenPointHaloMax` 个（按距离取近）。加法混合 + ZTest Always（不被建筑遮挡），纯视觉，不改建筑模型/材质/存档；关掉 `tenPointHalo` 即消失。v0.11.6–v0.11.8 的屏幕描边是实验性选项（`tenPointOutline`，默认关）。
