# DSP 在线调试环境 · 使用说明

> 本文件只讲**怎么用**。所有踩过的坑、事故经过、排查细节见
> [`在线调试环境-踩坑与排查.md`](在线调试环境-踩坑与排查.md)。
> 环境已在本机实测：`BepInEx 5.4.17 + Doorstop 3.4.0 + DspBridge 插件 + DspMcpBridge`，全套件 8/8 通过。

## 0. 速读（给新对话 / 新接手的人）

- **作用**：让外部程序（脚本、MCP 客户端、LLM）在游戏运行时读取 DSP 游戏状态，并可开关暂停等写操作。
- **组成**：游戏内插件 `BepInEx\plugins\DspBridge\DspBridge.dll`（只读 HTTP 快照）+ 独立进程 MCP server `DspMcpBridge`（把 HTTP 包成 MCP 工具）+ 一组 PowerShell 工具（启停、等待就绪、日志、截图点击、自检）。
- **平时只需要 4 条命令**（都在 `工具包\` 目录下执行）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode doctor    # 不开游戏先自检
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode up        # 启动游戏并等桥接就绪
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test-all.ps1 -RequireLive    # 全套验证
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode down      # 关游戏
```

- **本机两个副本**：工作区工具包 `C:\XCM\DSP MOD`（根目录，源码 + `tools\`）与便携包
  `C:\XCM\DSP MOD\开发文档\DSP-MPD-runtime-debug`（自带 SDK、payload，命令完全一样）。
  日常用哪个都行，改代码/改 payload 时两边同步（见 §11）。
- **硬性边界**：固定版本组合 `BepInEx 5.4.17 + Doorstop 3.4.0`，不要升级、不要混用；游戏一律用
  `dev-loop.ps1`（Steam 启动），不要用 r2modman 的 Start modded 启动（原因见踩坑文档）。
- **不要载入缺少对应 mod 的旧存档**：会崩在 `DSP Mod Save Pre Load` 并退出游戏。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11 x64 |
| 权限 | 安装/部署游戏侧需要管理员（游戏在 `C:\Program Files (x86)\Steam\...`） |
| 游戏 | Steam 版 Dyson Sphere Program，AppID `1366540`，当前适版本 `2022.3.62.1451004` |
| 游戏目录 | `C:\Program Files (x86)\Steam\steamapps\common\Dyson Sphere Program` |
| .NET | 插件运行时：.NET Framework 4.7.2（随游戏环境）；MCP server 与构建：工具包内便携 .NET SDK `10.0.401`（无需系统安装） |
| 加载器 | **Doorstop 3.4.0 + BepInEx 5.4.17**（工具包 payload 已固定，勿换版本） |

网络：桥接只监听 `127.0.0.1:17890`，不对外；MCP server 走 stdio，不占端口。

## 2. 目录与关键文件

```
C:\XCM\DSP MOD\                                   ← 工作区（源码 + tools + game-side-patch）
├─ DspBridge\                                     ← 游戏内插件源码（net472）
├─ DspMcpBridge\                                  ← MCP server 源码（net10.0）
├─ tools\                                         ← 全部脚本、便携 SDK、refs、bepinex-lib
├─ game-side-patch\                               ← 要装进游戏的 payload（加载器 + core + 插件）
├─ 开发文档\
│   ├─ 在线调试环境-使用说明.md                    ← 本文件
│   ├─ 在线调试环境-踩坑与排查.md
│   └─ DSP-MPD-runtime-debug\                     ← 便携包（同一套东西的独立副本）
└─ .mcp.json / MCP-REGISTRATION.txt               ← MCP 客户端注册（指向 tools\run-dsp-mcp.cmd）

游戏目录\
├─ winhttp.dll                                    ← Doorstop 3.4.0 注入器
├─ doorstop_config.ini                            ← Doorstop 3 格式（[UnityDoorstop] + targetAssembly）
├─ BepInEx\core\                                  ← BepInEx 5.4.17 运行时
├─ BepInEx\plugins\DspBridge\DspBridge.dll        ← 桥接插件
├─ BepInEx\config\org.yourname.dspbridge.cfg      ← 桥接配置（首次启动游戏后生成）
├─ BepInEx\LogOutput.log                          ← 游戏内日志（每次启动重写）
└─ logs\（工具包内）                              ← dev-loop 归档的历次日志

%LOCALAPPDATA%\DSPBridge\runtime.json              ← 桥接运行时信息（端口/token/pid/allowWrites）
```

`runtime.json` 由插件在启动成功后写入，**游戏干净退出时自动删除**；里面含 Bearer token，不要外传。

## 3. 一次性安装 / 部署

工具包已自带 payload，正常情况直接跳到 §4。换机、重装游戏、或加载器被覆盖后，按顺序执行（管理员 PowerShell）：

```powershell
# 0) 进工具包
cd 'C:\XCM\DSP MOD\开发文档\DSP-MPD-runtime-debug'     # 或 C:\XCM\DSP MOD

# 1) 机器适配：校验便携 SDK/refs/库 → 写 machine.config.ps1/.mcp.json/MCP-REGISTRATION.txt → 编译两工程 → 离线套件
powershell -NoProfile -ExecutionPolicy Bypass -File tools\setup-machine.ps1 `
  -GameDir 'C:\Program Files (x86)\Steam\steamapps\common\Dyson Sphere Program'
#    期望结尾：MACHINE SETUP COMPLETE

# 2) 游戏侧安装：备份 → 装 Doorstop 3.4.0 + BepInEx 5.4.17 + DspBridge 插件 → 自检
powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-game-side.ps1
#    期望结尾：GAME-SIDE INSTALL COMPLETE（若加载器已被改成 Doorstop 4，重跑本步即可恢复）

# 3) 编译并部署插件（只在改了插件代码后需要）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-and-deploy.ps1
#    期望：deployed: DspBridge.dll (44032 bytes)

# 4) 自检 + 启动 + 验证
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode doctor
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode up
powershell -NoProfile -ExecutionPolicy Bypass -File tools\verify-live.ps1
```

备份位置：游戏目录下 `_backup_bepinex_<版本>_<时间戳>\`（core/config/patchers）与
`_backup_dsp_bridge_<时间戳>\`（加载器四件套 + 插件），需要还原时手动拷回。

## 4. 日常使用：`tools\dev-loop.ps1`

一条命令管启停、等就绪、日志、验证、截图点击。`-Mode` 取值：

| Mode | 作用 |
|---|---|
| `status` | 游戏进程 / runtime.json / `/health` / 日志诊断 / 日志尾部，只看不动 |
| `doctor` | **不启动游戏**做 9 组环境自检（加载器、core、插件、配置、端口、runtime、日志证据、r2modman profile） |
| `up` | 用 Steam `-applaunch 1366540` 启动，等桥接就绪后归档日志；`-RequireSave` 要求进到存档 |
| `down` | 优雅关闭游戏（等 `OnApplicationQuit`，插件会删 runtime.json） |
| `restart` | down + up，可用 `-Writes on\|off` 同时改写权限 |
| `cycle` | down + up + 跑 `verify-live.ps1`（回归用） |
| `log` | 打印日志尾部；`-Lines N`、`-Filter DspBridge`、`-Follow`、`-Back 1`（看上一次归档） |
| `verify` | 跑 `tools\verify-live.ps1` 的 14 项实测 |
| `watch` | 守护：定期打心跳，游戏掉了自动拉起（`-AutoRestart`、`-IntervalSec`、`-DurationSec`） |
| `shot` | 抓游戏窗口 PNG（`-Out` 指定路径，默认 `logs\shot-<时间戳>.png`）；黑帧时用 `-Foreground` |
| `click` | 按物理像素点击（`-X -Y -Button left\|right\|double`），菜单操作先 `shot` 看坐标 |
| `key` | 发按键（`-Key escape\|enter\|tab\|space\|f1..f12\|up/down/left/right` 或 `-VK 27`，可 `-Repeat`） |

图形操作相关参数：`-Foreground`（先切前台再抓/点，避免 PrintWindow 黑帧）、`-TimeoutSec`（等待就绪秒数，默认 300）、
`-GraceSec`（关闭宽限，默认 90）、`-NoArchive`（不归档日志）、`-Writes keep\|on\|off`（改 `AllowWrites`）。

常用组合：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode status
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode log -Lines 200 -Filter DspBridge
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode shot -Foreground
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode click -X 225 -Y 407 -Foreground
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode cycle -RequireSave
```

日志归档命名：`logs\LogOutput-<时间戳>-{ready,final,previous}-pid<pid>.log`。

## 5. 验证（任何改动后跑）

| 命令 | 检查 | 期望标记 |
|---|---|---|
| `tools\dev-loop.ps1 -Mode doctor` | 9 组环境自检，不需要游戏 | `DOCTOR OK`（exit 0） |
| `tools\verify-live.ps1` | 14 项：runtime.json、writes 默认关闭、401、health、pid 一致、schema、/state、未知 op 拒绝、catalog、set_pause 被拒、token 不回显 | `ALL LIVE CHECKS PASSED` |
| `tools\verify-mcp-live.ps1` | MCP server → cmd 启动器 → HTTP → 真游戏（含 `dsp_tail_log`、token 不进模型） | `ALL LIVE MCP CHECKS PASSED` |
| `tools\test-all.ps1` | 全部 8 套件（离线 6 + 实测 2） | `ALL SUITES PASSED` |
| `tools\test-all.ps1 -RequireLive` | 同上，要求游戏在跑 | `ALL SUITES PASSED` |

`verify-live` 在游戏停主菜单（`gameLoaded=false`）时会跳过存档内检查并打印 NOTE，这是预期行为。

## 6. 游戏内 HTTP 接口

- 地址：`http://127.0.0.1:17890`；认证：`Authorization: Bearer <runtime.json 里的 token>`；无 token → `401`。
- 端点：

| 方法与路径 | 说明 |
|---|---|
| `GET /health` | 连通状态：pid、schemaVersion、gameLoaded、snapshotTick、unityVersion |
| `GET /state` · `GET /snapshot` | 最近一次只读快照（后台线程每 30 帧整串替换，主线程不阻塞） |
| `POST /command` | `{"op":"<op>","args":{...}}`，未登记 op 一律拒绝 |

- op 表（`CommandRouter`）：

| op | 级别 | 说明 |
|---|---|---|
| `get_health` | L0 | 健康状态 |
| `get_state` | L0 | 运行时状态 |
| `get_catalog` | L0 | 原型表统计 |
| `get_power` | L0 | 电网信息 |
| `get_planet_power` | L0 | 指定星球电力（`planetId`/`planetIndex`） |
| `list_planets` | L0 | 已实例化星球（分页） |
| `find_items` | L0 | 按名字找物品原型 |
| `get_log_tail` | L0 | 游戏日志尾部（`lines`） |
| `get_audit` | L0 | 审计日志 |
| `set_pause` | L1 | 暂停/继续（`paused`）——**受 `AllowWrites` 开关保护** |

- `AllowWrites=false`（默认）时，写 op 返回 `writes_disabled`，不执行。

## 7. MCP server（`DspMcpBridge`）

启动器 `tools\run-dsp-mcp.cmd`（相对路径、重定向 SDK 环境变量、stdout 只输出 JSON-RPC）。
stdin/stdout 走 MCP；诊断信息一律走 stderr。

**Tools（9 个）**：`dsp_health`、`dsp_get_state`、`dsp_get_catalog`、`dsp_get_planet_power`、`dsp_list_planets`、
`dsp_find_items`、`dsp_tail_log`、`dsp_get_audit`、`dsp_set_pause`（唯一写工具）。

**Resources（4 个，只读）**：`dsp://health`、`dsp://state`、`dsp://catalog`、`dsp://planets`。

注册到 MCP 客户端：用 `.mcp.json`（本机已指向 `C:\XCM\DSP MOD\tools\run-dsp-mcp.cmd`），其余客户端写法见
根目录 `MCP-REGISTRATION.txt`。注册后**重启客户端**才会生效；工具没出现先跑 `verify-mcp-live.ps1`。

## 8. 配置项（`BepInEx\config\org.yourname.dspbridge.cfg`）

首次启动游戏后自动生成；改完需重启游戏生效。

| 键 | 默认 | 说明 |
|---|---|---|
| `Port` | `17890` | 监听端口（仅 127.0.0.1） |
| `Token` | 随机 | 首次生成后固定；runtime.json 里同一份 |
| `AllowWrites` | `false` | 是否允许 L1 写 op |
| `SnapshotEveryFrames` | `30` | 快照刷新间隔（帧） |
| `AuditLogToFile` | `true` | 写 op 是否落审计文件 |

## 9. 写权限（L1）

```powershell
# 开关需要重启游戏（配置在启动时读入）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode restart -Writes on
# 此时 runtime.json 中 allowWrites=true，set_pause 会被主线程执行：
#   POST /command {"op":"set_pause","args":{"paused":true}}  -> {"schemaVersion":1,"requested":true,"isPaused":false}
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dev-loop.ps1 -Mode restart -Writes off   # 用完立刻恢复
```

## 10. 限制与边界

- **版本固定**：`BepInEx 5.4.17 + Doorstop 3.4.0` 是唯一可用组合（Doorstop 4 无法驱动 5.4.17，混代静默失败）。
- **改配置/加 op 需重启游戏**：插件没有热重载；代码层 `Assembly-CSharp` 改不了，只能靠已核实的反射入口读。
- **主菜单无存档数据**：`gameLoaded=false` 时存档相关 op 没有内容，属正常；`set_pause` 在菜单态 `isPaused` 会保持 false。
- **不要用 r2modman 的 Start modded 启动**：它会把 profile 文件覆盖进游戏目录，桥接消失。必须用 r2modman 时先跑
  `tools\install-r2modman-profile.ps1`，但本项目统一推荐 `dev-loop.ps1`。
- **不要载入缺 mod 的旧存档**：会崩在 `DSP Mod Save Pre Load` 并退出游戏。
- 像素兜底（`shot/click/key`）是最后的办法：先 `shot` 看坐标，再 `click`；窗口最小化/黑帧时加 `-Foreground`。

## 11. 维护与同步

- 改了 `DspBridge` 源码：`build-and-deploy.ps1` 编译 → 部署到游戏 → 把新 `DspBridge.dll` 同步到
  `game-side-patch\BepInEx\plugins\DspBridge\`（否则 `install-game-side.ps1` 装回旧插件）。
- 工作区与便携包是两份独立副本：脚本/源码/payload 改动后两边同步，并各自跑一次 `-Mode doctor` 确认自洽。
- 改了加载器/core payload：重跑 `install-game-side.ps1`；用过 r2modman 的话再跑一次 `install-r2modman-profile.ps1`。
- 换机器：删掉旧 `tools\machine.config.ps1` 后按 §3 重新执行。

## 12. 常见现象 → 先看哪里

| 现象 | 先看 |
|---|---|
| `-Mode up` 超时 / 日志里没有 `[DspBridge]` 行 | 踩坑文档 §1（加载器代际）与 §2（启动方式） |
| `/health` 连不上、401、token 不对 | 踩坑文档 §5（runtime.json/端口/401） |
| `doctor` 报 FAIL | 按 doctor 输出的修法提示操作；含义见踩坑文档 §1–§4 |
| 游戏启动后闪退/停在加载 | 是否载入了缺 mod 的存档（§10） |
| MCP 工具在客户端里看不到 | 踩坑文档 §5（启动器/注册/stdio 日志） |
